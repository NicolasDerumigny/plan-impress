# AGENTS.md

Notes for an AI agent working on this repository. Read this before editing: most
of what is here was measured against LibreOffice, not copied from documentation
that turned out to be wrong or incomplete.

## What this is

A LibreOffice Impress extension (`org.devsys.planimpress`) that inserts agenda
slides: one overview slide before the first section, plus one identical plan
slide at the top of each section where only the current section is drawn in the
text colour. A `Plan` menu provides *Insert Plan Slides*, *Remove Plan Slides*,
*Settings…* and *Toggle Debug Log*.

## Layout

```
src/                     the extension package: this tree IS the inside of the .oxt
  Addons.xcu             menu + icons
  description.xml        metadata, version, dependencies
  META-INF/manifest.xml  which files are configuration data / Python components
  handler.py             the com.sun.star.task.Job implementations (menu commands)
  plan_impress/
    core.py              all document-model work (sections, pages, shapes)
    dialog.py            settings dialog + message boxes
    config.py            settings persistence, colour helpers, logging
  icons/                 PNGs generated by dev/make_icons.py
dev/                     harness: run/install/package scripts, debug reproducers
tests/run_tests.py       the test suite (plain Python, no framework)
tests/make_fixture.py    creates tests/fixtures/sections.odp
Makefile                 make | install | start | stop | test | unit | icons | fixture | clean
```

`out/` and `loprofile/` are generated and git-ignored. Never commit them.

## Commands

```sh
make test       # install + full suite against the dev office (needs X; start_ui.sh starts Xvfb)
make unit       # the tests that need no office (colour helpers, dialog layout)
make install    # stop office, package src/, unopkg add, start office
python3 tests/run_tests.py <substring>     # run a subset of the tests
```

The dev office is a **separate** LibreOffice with its own profile
(`loprofile/`) and its own UNO socket (port 2009). Do not kill the user's own
soffice; `dev/stop_lo.sh` matches only the dev instance by its profile path, and
`unopkg` must run while the dev soffice is **stopped** (it prints
`ERROR: unopkg failed.` otherwise). Extension code is cached inside the office
process, so a change only takes effect after `make install` (which restarts it).

## Conventions

* Python 3, no dependencies beyond what LibreOffice ships. Keep the code
  compatible with the Python embedded in LibreOffice 7.x (3.8+), i.e. no
  walrus-dependent cleverness, no 3.10-only syntax.
* `core.py` contains only document-model code and never imports `dialog.py`;
  that separation is what lets the tests drive `core` directly.
* Errors the user should see are raised as `core.PlanError` with a message that
  says what to do next; anything else is logged to `error.log` and reported.
* Keep the "why" comments. The unusual lines in this codebase exist because of a
  specific measured LibreOffice behaviour, and a well-meaning cleanup that
  removes one of them reintroduces a real bug.

## LibreOffice facts this code depends on

All of these were verified on LibreOffice 26.8.2.2 on Linux. Each one is
reproducible with a script in `dev/`.

### Packaging

1. **`description.xml` dependency spelling.** Use
   `<lo:LibreOffice-minimal-version value="7.0" d:name="LibreOffice 7.0"/>` in
   the namespace `http://libreoffice.org/extensions/description/2011`. An element
   with the *same name* in the 2006 namespace fails with
   `unsatisfied dependencies` whatever value it carries, and
   `OpenOffice.org-minimal-version` is compared against
   `ReferenceOOoMajorMinor` (`4.1` in `program/versionrc`), so asking for `"7.0"`
   there fails as well. `dev/dep_probe.py` walks through every spelling.
2. **Only register what must be registered.** `META-INF/manifest.xml` declares
   `Addons.xcu` (`configuration-data`) and `handler.py`
   (`uno-component;type=Python`). The `plan_impress` package is *not* declared:
   `handler.py` adds its own folder to `sys.path` and imports it normally.
3. **No `com.sun.star.*` imports at module level** in anything the extension
   manager loads. During registration those imports fail
   (`ImportError: No module named 'com'`) and registration is skipped with only
   a warning on stderr — the extension then looks installed but has no menu and
   no error message. Import them inside functions/methods. `handler.py`
   additionally guards `from com.sun.star.task import XJobExecutor` at module
   level and falls back to `object`, because the class definitions must be
   evaluable at registration time.
4. `unopkg` does not replace a running installation: stop the office first, and
   `unopkg remove <identifier>` before `add` when testing packaging changes.

### Menu (`Addons.xcu`)

5. Top-level menus are added with `OfficeMenuBarMerging`. `MergePoint` is a
   **menu path of item commands** separated by backslashes — `.uno:SlideShowMenu`
   puts us after *Slide Show*. `MergeCommand` accepts
   `AddAfter | AddBefore | Replace | Remove`; `MergeFallback` accepts
   `AddPath | Ignore` (`AddLast` is a *toolbar* token and is silently ignored
   here).
6. `MergeContext` and each item's `Context` are matched against the module
   identifier `ModuleManager::identify()` returns for the document model — for
   Impress that is `com.sun.star.presentation.PresentationDocument`. A wrong
   value fails **silently**: the menu just never appears.
7. A submenu node needs `Title` + a `Submenu` child and must **not** carry a
   `URL`; the leaf items need `URL` + `Title` + `Target=_self`.
8. Icons go under `AddonUI/Images`, keyed by the same `URL` as the menu item,
   with `%origin%/icons/…` paths (`%origin%` = the extension's own folder).
9. The configuration is only re-read at startup; after changing `Addons.xcu`
   you must restart the office (`make install` does it).

### Calling into Python

10. Menu items use `service:<implementationName>?<args>` bound to
    `com.sun.star.task.Job`, registered with `unohelper.ImplementationHelper()`
    in `handler.py`. LibreOffice then calls `XJobExecutor.trigger(args)`. This
    is the SDK's own pattern; `vnd.sun.star.script:` URLs are fragile because
    they embed the installed `.oxt` file name and
    `location=user:uno_packages`.
11. **Run the work inline in `trigger()`.** Executing the same document work
    from a Python **worker thread crashes the office** (`free(): invalid
    pointer`, `Unspecified Application Error`, whole process gone). The
    `.uno:MovePageUp/Down` commands are nevertheless asynchronous, so
    `core.insert_page_at()` polls for the index change instead of hoping.
    `PLAN_IMPRESS_DEFER=1` switches to a `com.sun.star.awt.Timer` main-loop
    deferral; keep that path working — it is the debugging tool for dispatch
    ordering.

### The document model

12. **Sections.** `doc.SlideSections` is a
    `sequence<com.sun.star.beans.PropertyValue>` whose values are themselves
    property-value sequences (`Name`, `Id`, `SlideNameList`). Writing it back
    only works when the nested values carry an explicit `uno.Any` type:
    `uno.Any("[]string", tuple(names))` and
    `uno.Any("[]com.sun.star.beans.PropertyValue", inner)`. Plain tuples are
    **silently dropped** — the assignment appears to succeed and nothing
    changes. Sections store slide *names*, not positions; `start` has to be
    derived (`core.get_sections`). Empty sections are kept by LibreOffice and
    are ignored here.
13. **`XDrawPages.insertNewByIndex(k)` inserts *after* position `k`**, clamps
    `k` to the page count, and can therefore never reach index 0. The container
    has no reorder method. `core.insert_page_at()` compensates: insert, then
    walk the page into place with `.uno:MovePageUp` / `.uno:MovePageDown`.
14. Those move commands act on the slide the **view** has selected, so
    `controller.setCurrentPage(page)` first. `controller.select(page)` does
    **not** work (measured: the page never moves — `dev/debug_move.py`). They
    are also asynchronous, hence the polling in `_wait_for_move`.
15. Insertions do **not** shift section membership: sections must be rewritten
    after every insertion (that is why `insert_plan` recomputes the whole list
    at the end and inserts bottom-up so the pending targets stay valid).
16. **Deleting a slide that anchors a section corrupts the section list**
    (measured: three sections became two with the wrong slides in them). So
    `remove_plan_slides()` snapshots the cleaned section lists first and
    rewrites them after the deletions. Do not "simplify" that.
17. `com.sun.star.presentation.SubtitleTextShape` raises
    `ServiceNotRegisteredException`; `com.sun.star.presentation.OutlinerShape`
    and `com.sun.star.drawing.TextShape` work. `core.BODY_SERVICES` tries them
    in that order.
18. Never test a shape type with `"Title" in shape.ShapeType` — the body
    placeholder's type is `...SubtitleTextShape`, which also contains "Title".
    Use `supportsService("com.sun.star.presentation.TitleTextShape")`
    (`core._is_title`).
19. **`CharHeight` is a point size; every geometry property is 1/100 mm.** Never
    derive one from the other: the original `height / 100` formula produced a
    262 pt heading (`dev/debug_sizes.py` prints the shape, paragraph and portion
    values). `core._master_char_height()` takes the size from the master
    placeholder (44 pt title / 32 pt body in the default master) and falls back
    to `_TITLE_PT`/`_BODY_PT`; `_fit_point_size()` shrinks the list so all
    sections still fit under the heading, and `_UNITS_PER_POINT` (35.28, not
    3528) is the only place the conversion happens.
20. **Do not copy a master placeholder's rectangle blindly.** The default
    Impress master keeps its title placeholder at `y = -32 mm` about two thirds
    of the page tall; used verbatim the heading is drawn outside the slide.
    `core._rect()` takes the rectangle only when it fits on the page and
    otherwise uses the computed fallback. Impress also re-snaps a presentation
    placeholder to the master and auto-grows it, so the rectangle you set is not
    always the one you read back — check the rendered result, not the property.
21. Presentation placeholders **anchor their text in the middle of the box**, so
    a one-line heading floats down into the body; `_make_text_shape` sets
    `TextAnchor` (awt `TOP` = 0) and `TextAnchorKind` (drawing `TOP` = 1).
22. Per-paragraph colour is set on the paragraphs of `createEnumeration()`
    (`_paint_paragraphs`), and a plain-text shape created with `setString()`
    treats `\n` as a paragraph break.

### AWT (`dialog.py`)

23. `dialog.Model = model` **raises** (`UnknownPropertyException: ... property
    is readonly`) — use `dialog.setModel(model)`.
24. `XNameContainer.insertByName()` on a dialog model **rejects** a
    `sequence<PropertyValue>` that carries a `Servicename`
    (`IllegalArgumentException`). Create the control's own model service
    (`com.sun.star.awt.UnoControlEditModel`, `...ButtonModel`,
    `...ListBoxModel`, `...FixedTextModel`), set the properties on it, and insert
    that object. `dev/debug_dialog.py` demonstrates both failures.
25. Sequence properties need explicit typing: `StringItemList` must be
    `uno.Any("[]string", tuple(...))`, `SelectedItems` `uno.Any("[]short", ...)`.
    `SelectedItems` is **0-based** on the model, and setting it before
    `createPeer()` is what preselects the current master slide.
    `getControl(name)` returns a proxy with a limited method set — `selectItem()`
    is a no-op and `getPropertyValue()` is missing; read/write style properties
    through `control.Model` / `dialog.Model.getByName(name)`.
26. The dialog is built as `_field_specs(values, masters)` → `(name, model
    service, [(property, value)])` triples, deliberately separated from UNO
    object creation so `tests/run_tests.py` can assert the layout with no
    display. Every control must fit inside `DIALOG_WIDTH`/`DIALOG_HEIGHT`; the
    test enforces it.
27. Message boxes: `Toolkit.createMessageBox(parent, type, buttons, text)` with
    `MessageBoxType` `0|3|4` (message/warning/error) and `MessageBoxButtons`
    `1` (OK) or `5` (Yes/No); `execute()` returns `MessageBoxResults`
    (`6` = Yes). Always `dispose()` in a `finally`, and never let a reporting
    failure swallow the real error.
28. `setTitle()` works on the dialog, `setPropertyValue("Title", …)` does not.

### Out-of-process test scripts

29. A remote document proxy does **not** expose `getComponentContext()`, so
    `core`'s functions take an optional `ctx` argument (`insert_plan(doc,
    settings, ctx)`). Keep it optional — the in-process Job relies on the
    default — and pass the connected context from tests.
30. Tests need a controller and a frame (moving slides and dispatching commands
    both require one), so they load documents **non-hidden** against the UI-mode
    dev office. `lo.open_doc(..., hidden=False)` waits for the controller.
31. The office logs to `out/soffice.log`. The extension's own logs are
    `loprofile/user/planimpress/error.log` (always written) and `debug.log`
    (only with the `debug` marker file in that folder, or
    `PLAN_IMPRESS_DEBUG=1`); the *Toggle Debug Log* menu item flips it.

## Testing notes

`tests/run_tests.py` has no framework: `@test` collects functions, a `Skip`
exception reports "not installed" without failing, and an argument filters by
substring (`python3 tests/run_tests.py dialog`). Tests that need the installed
extension are skipped when it is not installed, so `make unit` is useful without
packaging.

The suite covers: settings round-trip and corrupt-file tolerance, colour
helpers, the point/unit conversion, dialog layout *and* a real control model
with a native peer, the inserted layout (position of every plan slide,
per-paragraph colours, the overview outside all sections), readable font sizes
with nothing drawn off the slide, idempotency and clean removal, the
master-slide setting, `Addons.xcu` registration read back through the
configuration provider, and the `service:` URL dispatch path a menu click takes.

Things that are easy to break and are covered: re-running `insert_plan` must
yield the identical slide list (this is what caught the section-corruption bug),
and `remove_plan` must return to the original seven slides and be harmless when
there is nothing to remove.

### Looking at the result

Assertions cannot tell you a slide looks right, and a font size that is wrong by
a factor of ten passed every test once. To see the generated deck: export a
document with the plan slides inserted to PDF
(`storeToURL(..., FilterName=impress_pdf_Export)`) and rasterise it with
`pdftoppm`/`montage`, then look at the images. `dev/debug_sizes.py` prints the
`CharHeight` at shape/paragraph/portion level plus the rectangles, which is
usually the faster way to spot a layout problem.

## If something is broken

1. Is the extension registered?
   `unopkg -env:UserInstallation=file://$PWD/loprofile list` — look for
   `is registered: yes` under each bundled package.
2. Does the office still have the old code? Restart (`make install`).
3. Read `loprofile/user/planimpress/error.log` and `out/soffice.log`.
4. Turn on the debug log and reproduce.
5. Reproduce in isolation with one of the `dev/debug_*.py` / `dev/dep_probe.py`
   scripts before changing `src/` — every surprising behaviour in this project
   was nailed down that way, and the answer usually is one of the numbered facts
   above.
